# 部署与运维

本文覆盖 Docker Desktop 部署、Tailscale Serve 暴露订阅入口、备份恢复、升级回滚与故障排查。

对应开发文档第 9、10、12 节。设计文档里的 `http://localhost:443/admin` 是**本机管理地址**,
端口号虽然是 443,容器内外都走 HTTP,HTTPS 由 Tailscale 在外层终止。

---

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 主机 + Docker Desktop(WSL2 后端) |
| Docker | 24 以上,含 Compose v2(`docker compose version` 可用) |
| Tailscale | 已登录 `sisi-laptop`,MagicDNS 名称 `sisi-laptop.tail921448.ts.net` |
| 端口 | 主机 443 空闲(仅绑定 `127.0.0.1`,不占用局域网) |
| 磁盘 | `/data` 所在盘预留空间;SQLite 单用户负载很小 |

## 2. 首次部署

### 2.1 准备配置文件

```powershell
cd D:\桌面\sisi_apps\SisiCalendar
Copy-Item .env.example .env
notepad .env
```

至少确认以下项:

```dotenv
DATA_DIR=/data
ADMIN_USERNAME=admin
# 推荐:先算出哈希再填,避免明文口令进入 .env
# ADMIN_PASSWORD_HASH=$argon2id$v=19$m=65536,t=3,p=4$....
SESSION_SECRET=            # 留空则首次启动自动生成并写入 /data/session_secret
DEFAULT_TIMEZONE=Australia/Brisbane
SUBSCRIPTION_URL=https://sisi-laptop.tail921448.ts.net/calendar
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_USERNAME=you@example.com
SMTP_PASSWORD=应用专用密码
SMTP_FROM_ADDRESS=you@example.com
```

生成管理员口令哈希(明文不会写入任何文件):

```powershell
uv run python -m app.cli hash-password
```

> 如果既没有 `ADMIN_PASSWORD_HASH` 也没有 `ADMIN_PASSWORD`,首次启动会随机生成口令并
> **只在容器日志里打印一次**,同时把哈希写入 `/data/admin.hash`。错过日志就用
> `docker compose exec calendar python -m app.cli credential` 查看来源,或重新注入哈希。

### 2.2 启动

```powershell
docker compose up -d --build
docker compose logs -f calendar
```

启动流程会自动完成:`/data` 目录准备 → Alembic 迁移到最新版本 → 数据库与 ICS 一致性检查
→ 恢复中断的发信任务 → 启动后台任务(每分钟修复 ICS、轮询邮件队列)。

默认 Compose 配额为 `256 MiB` 内存、`0.50 CPU` 和 64 个进程/线程。该配额面向单用户、
单 Uvicorn 进程部署，并为启动迁移、ICS 导出和邮件附件构造保留峰值余量。若出现容器被
OOM 杀死，应优先调高 `mem_limit`，不要关闭健康检查或数据一致性任务。

### 2.3 本机验证

```powershell
curl.exe -i http://localhost:443/healthz
curl.exe -i http://localhost:443/readyz
curl.exe -i http://localhost:443/calendar
```

- `/healthz` 返回 `{"status":"ok"}` 表示进程存活。
- `/readyz` 返回 `200` 且 `checks` 全为 `ok` 表示数据库、数据目录与导出状态都正常。
- `/calendar` 返回 `Content-Type: text/calendar; charset=utf-8`。

浏览器打开 `http://localhost:443/admin` 登录后应看到月历视图。

### 2.4 关闭对外暴露(重要)

Compose 里端口必须写成 `127.0.0.1:443:8000`。一旦省略主机 IP,Docker 会绑定 `0.0.0.0`,
管理界面就会出现在局域网中。可用下面的命令确认绑定地址:

```powershell
docker compose ps
netstat -ano | findstr :443
```

`netstat` 结果应只出现 `127.0.0.1:443`,不应出现 `0.0.0.0:443` 或 `[::]:443`。

### 2.5 配置邮件发信(可选)

邮件同步默认关闭。没有配置 SMTP 时,保存日程**不会**创建任何发信任务,订阅与 ICS 一切照常,
只是不会发邮件。代码不需要改动,只需要填环境变量。

#### 需要的环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `SMTP_HOST` | 是 | 发信服务器地址 |
| `SMTP_FROM_ADDRESS` | 是 | 发件人邮箱。**与 `SMTP_HOST` 同时存在才算「已配置」** |
| `SMTP_PORT` | 否 | 默认 `587`(STARTTLS);SSL 一般用 `465` |
| `SMTP_SECURITY` | 否 | `starttls`(默认)/ `ssl` / `none` |
| `SMTP_USERNAME` | 否 | 留空则不认证(仅内网中继适用) |
| `SMTP_PASSWORD` | 否 | **应用专用密码 / 授权码**,不是邮箱登录密码 |
| `SMTP_FROM_NAME` | 否 | 显示名,默认 `Sisi Calendar` |
| `SMTP_TIMEOUT_SECONDS` | 否 | 默认 30 |
| `MAIL_MAX_ATTEMPTS` | 否 | 默认 5 次 |
| `MAIL_BACKOFF_MINUTES` | 否 | 默认 `1,5,15,60,180` |

口令只能通过环境变量或 Docker Secret 注入:不写数据库、不进日志、界面只显示「已注入/未注入」。
`.env` 已被 `.gitignore` 排除,不要提交。

#### 常见邮箱服务商

| 服务商 | HOST | 端口 / 安全方式 | 用户名 | 口令 |
|---|---|---|---|---|
| Gmail | `smtp.gmail.com` | 587 / `starttls` | 完整邮箱地址 | **应用专用密码**(需先开两步验证) |
| QQ 邮箱 | `smtp.qq.com` | 465 / `ssl` | 完整邮箱地址 | **授权码**(设置 → 账户 → 开启 SMTP) |
| 163 邮箱 | `smtp.163.com` | 465 / `ssl` | 完整邮箱地址 | **授权码** |
| Outlook / M365 | `smtp.office365.com` | 587 / `starttls` | 完整邮箱地址 | 应用密码(开了两步验证时) |
| iCloud | `smtp.mail.me.com` | 587 / `starttls` | 完整邮箱地址 | **App 专用密码** |
| 自建 Postfix | 你的域名 | 587 / `starttls` | 视配置 | 视配置 |

> 用主账号密码通常会被拒绝(报 `SMTPAuthenticationError`),务必用应用专用密码或授权码。

#### 生效与验证

```powershell
# 1. 写入 .env(注意用引号包住含特殊字符的口令)
notepad .env
#   SMTP_HOST=smtp.qq.com
#   SMTP_PORT=465
#   SMTP_SECURITY=ssl
#   SMTP_USERNAME=you@qq.com
#   SMTP_PASSWORD=你的授权码
#   SMTP_FROM_ADDRESS=you@qq.com
#   SMTP_FROM_NAME=Sisi Calendar

# 2. 重启容器让环境变量生效(改 .env 不会自动生效)
docker compose up -d

# 3. 打开设置页验证
start http://localhost:443/admin/settings
#   「SMTP 发信配置」应显示「已配置」
#   先点「测试连接 / 发送测试邮件」(留空收件地址 = 只测连接)
#   再填自己的邮箱点一次,确认能收到
```

设置页上的 SMTP 区块是**只读**的——出于安全考虑,凭据只能在 `.env` 里改。

#### 添加收件人并发出第一封

1. 在 `/admin/settings` 的「同步人员」里填邮箱,勾选隐私确认后点「添加」。
   该人员会收到**完整日历**,请逐位确认。
2. 设置同步人员本身不会发信。要让对方立刻拿到当前日历,去 `/admin/sync` 点
   「向当前人员发送最新版」(会二次确认)。
3. 之后每次在界面上「保存并同步」,或通过 Agent 接口新建日程,都会自动向所有**启用**的人员
   各发一封带完整 `calendar.ics` 的邮件。

> 注意:配置 SMTP 之前产生的历史日程不会补发。上面的「发送最新版」就是为此准备的——
> 它会把当前完整日历发给所有启用人员各一次。

#### 失败时的表现

- 每位收件人**单独发送**:一个人失败不影响其他人。
- 失败按 `1,5,15,60,180` 分钟退避重试,达到 `MAIL_MAX_ATTEMPTS` 后标记为失败。
- `/admin/sync` 的邮件队列表格逐条显示**操作时间**(任务创建时刻)、**发送时间**、重试次数、
  下次重试时间与错误摘要,并支持逐条手动重试。时间按日历默认时区显示(鼠标悬停可看秒)。
- 附件永远取自该任务记录的不可变快照:即使中间又改了几次日历,重试发的仍是那一版,
  不会「冒充新版」。
- 邮件失败**不会**回滚日程或 ICS,也不会影响订阅。

#### 邮件排错

| 现象 | 原因与处理 |
|---|---|
| 设置页一直显示「未配置」 | `SMTP_HOST` 或 `SMTP_FROM_ADDRESS` 为空;或改了 `.env` 没重启容器 |
| `SMTP 认证失败` | 用了登录密码而不是授权码/应用专用密码;或该邮箱未开启 SMTP 服务 |
| `无法连接 SMTP 服务器` | 主机名或端口写错;端口被网络/防火墙拦截;`SMTP_SECURITY` 与端口不匹配 |
| 证书校验失败 | 服务器证书不受信任(常见于自建中继)。**不要**关闭校验;改用受信任证书或换端口 |
| 全部成功但收不到 | 进了对方垃圾箱;检查发件域名的 SPF/DKIM |
| 只有个别人失败 | 单个地址被对方服务器拒收;修正后在该行点「重试」 |

### 2.6 日历设置(默认时区)

`/admin/settings` 的「默认时区」是下拉框,按地区分组列出 30 个常用时区,每项前面是**序号**:

```text
亚洲   1. 北京时间(Asia/Shanghai)      11. 悉尼时间(Australia/Sydney)
       2. 香港时间(Asia/Hong_Kong)     12. 布里斯班时间(Australia/Brisbane)
       …                                 …
```

- 序号顺序**固定不变**(只会在表尾追加),所以可以放心把它写进快捷指令或脚本;
  `timezone` 字段填序号、中文名或 IANA 名都行。
- 下拉框只放常用时区;环境配置里写过的其它 IANA 名(如 `Asia/Kathmandu`)会作为
  「当前值,不在常用清单中」保留在选项里,不会被静默改掉。
- 新建/编辑日程页的时区输入框也接受序号与中文名,悬浮候选里能看到同样的编号。
- 完整清单与解析规则见 [`docs/static/app-timezones.md`](static/app-timezones.md)。

## 3. Tailscale Serve:只暴露 /calendar

> **警告一**:`tailscale serve` 是**整机配置**。在已有路由的机器上操作前必须先保存快照,
> 避免误删其他入口。
>
> **警告二**:Tailscale Serve 是**剥前缀**代理——挂载 `/calendar` 之后,请求 `/calendar/xxx`
> 会以 `/xxx` 转发给后端。因此目标地址里**必须**重复写上 `/calendar`,否则
> `/calendar/admin` 会命中后端的管理首页,把管理界面暴露给整个 tailnet。这不是假设:
> 首次部署时用不带路径的目标实测,`/calendar/login` 返回了 200(登录页)。

```powershell
# 1. 先看现状并留存
tailscale serve status | Tee-Object -FilePath tailscale-serve-backup.txt

# 2. 新增 /calendar 路由(追加路径,不会重置 / 与 /dsh 等其他入口)
#    注意目标里必须带上 /calendar:https://<节点>/calendar -> http://127.0.0.1:443/calendar
tailscale serve --bg --yes --https=443 --set-path=/calendar http://127.0.0.1:443/calendar
```

期望结果(原有的 `/`、`/dsh` 必须原样保留):

```text
https://sisi-laptop.tail921448.ts.net (tailnet only)
|-- /         proxy http://127.0.0.1:3081
|-- /dsh      proxy http://127.0.0.1:3081
|-- /agent    proxy http://127.0.0.1:443/api/agent     # 开启远程 Agent 后才有
|-- /calendar proxy http://127.0.0.1:443/calendar
```

路径映射关系:

| 对外地址 | 转发到后端 | 结果 |
|---|---|---|
| `/calendar` | `/calendar` | 200 + `text/calendar` |
| `/calendar/` | `/calendar/` | 307 跳回 `/calendar`(Starlette 去尾斜杠) |
| `/calendar/admin` | `/calendar/admin` | 404(后端无此路由) |
| `/calendar/calendar.ics` | `/calendar/calendar.ics` | 404(该别名只在裸路径可用) |

回退方式:把 `docs/tailscale-serve-before-calendar.txt` 的内容对照后重新执行 `tailscale serve`
相应命令,或 `tailscale serve --https=443 off` 关闭全部 443 代理。

### 3.1 必须确认不能访问的路径

```powershell
$h = 'https://sisi-laptop.tail921448.ts.net'

# 订阅入口必须可用
curl.exe -i "$h/calendar"                 # 期望 200 + text/calendar; charset=utf-8

# 管理面必须不可达:以下全部期望 404(不能是 200/303/401)
foreach ($p in '/calendar/admin','/calendar/login','/calendar/api/v1/events',
               '/calendar/readyz','/calendar/healthz','/calendar/settings') {
  "{0,-32} {1}" -f $p, (curl.exe -s -o NUL -w '%{http_code}' "$h$p")
}
```

`/admin`、`/api/v1/events` 这类**裸路径**不会到达本服务(它们会命中 `/` 路由指向的其他服务),
因此返回 401/404 都属正常;真正要守住的是 `/calendar/*` 下的 404。

如果 `/calendar/login` 返回 200,说明目标地址漏写了 `/calendar`,立即按上面的命令重配。

### 3.2 ACL 建议

在 tailnet ACL 中只允许指定用户或设备访问该节点的 Serve:

```jsonc
{
  "acls": [
    // 只有自己的设备可以访问 sisi-laptop 的 Serve 服务
    { "action": "accept", "src": ["autogroup:member"], "dst": ["sisi-laptop:443"] }
  ]
}
```

按需收紧到具体设备标签。**不要**启用 `tailscale funnel`——那会把私人日历暴露到公网。

### 3.3 iPhone 订阅

1. iPhone 打开 Tailscale 并确认已连接。
2. 设置 → 日历 → 账户 → 添加账户 → 其他 → 添加已订阅的日历。
3. 服务器填 `https://sisi-laptop.tail921448.ts.net/calendar`。
4. 关闭 Tailscale 时系统日历保留最后一条缓存;恢复连接后自动拉取新版本。

### 3.4 远程 Agent 接入(可选,默认关闭)

让本机之外的脚本 / LLM Agent / 快捷指令通过 HTTP 新建日程。

**默认是关闭的**:只要**两个来源都没有令牌**——`.env` 的 `AGENT_API_TOKEN` 为空,且平台内也没有
启用的令牌——`/api/agent` 全路径返回 404,等同不存在。
这是一个**可写的**对外接口,开启前请想清楚下面三点:

1. 拿到令牌的人就能往你的日历里写日程(并能给所有同步人员触发邮件)。
2. 令牌有两个来源,**取并集**:平台内创建的令牌(只存哈希,明文只在生成时显示一次)与
   `.env` 里的 `AGENT_API_TOKEN`(明文注入,可逗号分隔多个)。`.env` 那一路作为兜底保留:
   数据库损坏或忘记在平台上建令牌时仍能应急。
3. 接口只认 `Authorization: Bearer`,**不接受 Cookie 会话**,因此没有 CSRF 面;
   反之,浏览器里已登录的管理会话也不能调用它。

#### 在平台内管理令牌(推荐)

登录后进入 **设置 → 远程接入令牌**:

| 操作 | 说明 |
|---|---|
| 生成令牌 | 填名称(如「iPhone 快捷指令」)并勾选确认 → 页面显示**一次性明文**,复制后离开即无法再查看 |
| 改名 | 随时改,不影响令牌本身 |
| 停用 / 启用 | 临时冻结而保留记录;停用后下一次请求即 401 |
| 撤销 | 永久删除,不可恢复;撤销最后一枚令牌后 `/api/agent` 回到 404 |

安全约定:

- 数据库里**只保存 `sha256(token)` 哈希**,明文不进库、不进日志、不回显;
- 列表只显示**指纹**(哈希前 16 位),与审计日志里的 `agent:<指纹>` 一一对应,
  可据此判断是哪枚令牌在建日程;
- 令牌丢失(没复制到)时无法找回,只能撤销后重建;
- 该接口需要**登录 + CSRF**,匿名访问会被重定向到登录页。

#### 环境变量兜底(.env 路线)

不打算用平台界面时,也可以继续只用 `.env`;两处令牌同时有效。

#### 开启步骤

```powershell
# 1. 生成令牌并写入 .env(不要提交到版本库)
$token = python -c "import secrets;print(secrets.token_urlsafe(32))"
Add-Content .env "`nAGENT_API_TOKEN=$token"
docker compose up -d

# 2. 本机先自测(不经过 Tailscale)
#    请求体先写成无 BOM 的 UTF-8 文件,再用 --data-binary 发出去:
#    中文不会被控制台代码页破坏,也绕开各 shell 对 -d 里引号的不同解释。
$payload = @{
  title      = '本机自测'
  start_at   = '2026-11-03T14:00:00'
  end_at     = '2026-11-03T15:00:00'
  client_ref = 'smoke-1'
} | ConvertTo-Json -Compress
$body = Join-Path $env:TEMP 'sisi-agent-smoke.json'
[System.IO.File]::WriteAllText($body, $payload, [System.Text.UTF8Encoding]::new($false))

curl.exe -s -o NUL -w "HTTP %{http_code}`n" -X POST http://localhost:443/api/agent/events `
  -H "Authorization: Bearer $token" -H "Content-Type: application/json" `
  --data-binary "@$body"

# 期望 HTTP 201;若打印 200,说明这个 client_ref 之前已经建过(幂等重放,不是错误)。

# 3. 需要远程访问时,再追加 Serve 路由(同样要注意目标要带路径)
tailscale serve --bg --yes --https=443 --set-path=/agent http://127.0.0.1:443/api/agent
```

上面第 1、2 步必须整段粘进 **PowerShell**,不要拆开粘到别的 shell。`-d` 的写法在两种 shell 里正好相反,
用混了都不会只打印一个状态码:

| shell | 请求体写法 | 用错另一种写法的后果 |
|---|---|---|
| PowerShell | `-d '{\"title\":\"smoke\"}'`(单引号包住) | 用了 cmd 的 `-d "{\"title\":...}"`:PowerShell 不认 `\"`,JSON 里的 `,` 又被当成数组分隔符,`-d` 只拿到半截 `{title:smoke` → `422`,剩下的碎片被 curl 当成额外 URL → 打印 `HTTP 422HTTP 000` |
| cmd.exe | `-d "{\"title\":\"smoke\"}"`(双引号包住) | 用了 PowerShell 的 `-d '...'`:cmd 不把 `'` 当引号,请求体里混进字面的 `'` → `422`「请求体不是合法的 JSON」 |

cmd.exe 还不认行尾的反引号续行:把上面那个多行 PowerShell 片段整段粘进 cmd(换行被吞掉)时,
那两个 `` ` `` 会被 curl 当成额外 URL,输出形如 `422`n000`n000`n`——其中 `` `n `` 只是被原样打印的字面量。

两种 shell 各自的一行写法(**必须写在一行**;另外别存成 `.bat`,`.bat` 里 `%{http_code}` 会被当成变量):

```powershell
# PowerShell
curl.exe -s -o NUL -w "HTTP %{http_code}" -X POST http://localhost:443/api/agent/events -H "Authorization: Bearer <令牌>" -H "Content-Type: application/json" -d '{\"title\":\"smoke\",\"start_at\":\"2026-11-03T14:00:00\",\"end_at\":\"2026-11-03T15:00:00\",\"client_ref\":\"smoke-1\"}'
```

```bat
rem cmd.exe
curl.exe -s -o NUL -w "HTTP %{http_code}" -X POST http://localhost:443/api/agent/events -H "Authorization: Bearer <令牌>" -H "Content-Type: application/json" -d "{\"title\":\"smoke\",\"start_at\":\"2026-11-03T14:00:00\",\"end_at\":\"2026-11-03T15:00:00\",\"client_ref\":\"smoke-1\"}"
```

这两种一行写法都只适合纯 ASCII 的字段值。带中文的标题、或者字段一多,就请走上面的 UTF-8 文件方式——
那是最不容易出错的一种,两种 shell 都能用。任何 422 先看响应体的 `error.message` 与 `error.fields`:
`message` 是「请求体不是合法的 JSON」说明 shell 把请求体改坏了,`fields` 才指向字段本身。

第 3 步之后的映射关系(同样是剥前缀 + 拼接):

| 对外地址 | 转发到后端 | 结果 |
|---|---|---|
| `/agent/events` | `/api/agent/events` | Agent 新建日程 |
| `/agent/events/{id}` | `/api/agent/events/{id}` | Agent 回查自己建的事件 |
| `/agent/admin` | `/api/agent/admin` | 404 |

#### 调用示例

```powershell
$env:SISI_AGENT_TOKEN = '<令牌>'
$base = 'https://sisi-laptop.tail921448.ts.net/agent'

$body = @{
  title       = '和牙医的预约'
  start_at    = '2026-11-03T14:00:00'      # 不带偏移量时按 timezone 解释
  end_at      = '2026-11-03T15:00:00'
  timezone    = 'Australia/Brisbane'
  location    = '市中心诊所'
  description = '半年一次洗牙'
  client_ref  = 'dentist-2026-11-03'        # 幂等键,重试安全
} | ConvertTo-Json -Compress
$file = Join-Path $env:TEMP 'event.json'
[System.IO.File]::WriteAllText($file, $body, [System.Text.UTF8Encoding]::new($false))

curl.exe -s -X POST "$base/events" `
  -H "Authorization: Bearer $env:SISI_AGENT_TOKEN" `
  -H "Content-Type: application/json; charset=utf-8" `
  --data-binary "@$file"
```

响应(成功新建):

```json
{
  "id": "…", "uid": "…@sisi-calendar", "title": "和牙医的预约",
  "all_day": false, "timezone": "Australia/Brisbane",
  "start_at_utc": "2026-11-03T04:00:00Z", "start_local": "2026-11-03T14:00:00+10:00",
  "sequence": 0, "source": "agent", "client_ref": "dentist-2026-11-03",
  "duplicate": false,
  "sync": { "ok": true, "changed": true, "version": 12, "mail_created": 2, "error": null }
}
```

| 状态码 | 含义 |
|---|---|
| `201` | 新建成功,ICS 已重新生成 |
| `200` + `"duplicate": true` | 该 `client_ref` 已存在,返回原事件;不会重复建、不会重新发信 |
| `401` | 缺少或错误令牌(令牌被停用或撤销后也算) |
| `404` | 两个来源都没有令牌(`.env` 为空且平台内没有启用的令牌),接口视为不存在 |
| `422` | 字段校验失败,`error.fields` 给出逐字段原因 |
| `429` | 超过 `AGENT_RATE_LIMIT_PER_MINUTE`(默认 60/分钟),带 `Retry-After` |

即使 `sync.ok` 为 `false`(ICS 生成失败),事件也已经安全落库,后台会每分钟自动修复;
Agent 可以用 `GET /agent/events/{id}` 回查。

#### 支持的字段

`title`(必填,≤200)、`start_at`/`end_at`(定时事件,ISO 8601)、
`start_date`/`end_date`(全天事件,`end_date` 不含当天)、`all_day`、
`timezone`(IANA 名 / 中文名 / **序号**,见下)、`location`(≤500)、`description`(≤10000)、
`status`(`confirmed`/`tentative`/`cancelled`)、`rrule`(标准 RRULE)或
`recurrence`(每日/每周/每月/每年)+ `recurrence_until`、`client_ref`(幂等键,≤200)、
`duration_minutes`(1–10080,不给 `end_at` 时用它算结束时间)。

只能给 `start_at` 时,结束时间自动取 `duration_minutes`;再不给就用
`DEFAULT_EVENT_DURATION_MINUTES`(默认 60 分钟)。

`start_at` 接受这些写法(不带偏移量时按 `timezone` 解释):

```text
2026-11-03T14:00:00        2026-11-03 14:00        2026-11-03T14:00
2026-11-03                 2026/11/03 14:00        2026年11月8日 14:00
2026-11-8 9:5              2026-11-03T04:00:00Z    2026-11-03T14:00:00+10:00
```

请求体既可以是 `application/json`,也可以是 `application/x-www-form-urlencoded`
(表单里留空的字段视为未提供)。

#### iOS 快捷指令

快捷指令的「获取 URL 内容」用 **Form** 请求体最省事——不用手写 JSON,也就不用处理转义。

在 iPhone 上新建快捷指令,加入以下操作:

| 操作 | 配置 |
|---|---|
| 获取 URL 内容 | URL:`https://sisi-laptop.tail921448.ts.net/agent/events` |
| | 展开「显示更多」→ 方法:`POST` |
| | 请求体:`Form` |
| | 头部:`Authorization` = `Bearer <你的令牌>`(平台内生成的或 `.env` 里的都行) |

Form 字段按下表填(不需要的字段直接不添加):

| 字段 | 值 |
|---|---|
| `title` | 文本,或用「询问输入」/「听写文本」的结果 |
| `start_at` | 日期变量,或先用「格式化日期」输出 `yyyy-MM-dd HH:mm` |
| `duration_minutes` | `60`(可省略,省略时用服务器默认时长) |
| `timezone` | 可省略:省略时用服务器 `DEFAULT_TIMEZONE`(本部署即 `Australia/Brisbane`)。要显式写就填 IANA 名、**序号**(如 `1`)或中文名(如「北京时间」),**不能填偏移量**——见下方「timezone 怎么填」 |
| `location` | 可选 |
| `client_ref` | 可选;填一个每次唯一的值(如「提供输入」的 UUID),重试就不会重复建 |

一个「说一句话加日程」的流程示例:

```text
听写文本                        → 得到标题
询问输入(类型:日期与时间)      → 得到开始时间
格式化日期(自定义 yyyy-MM-dd HH:mm)→ 得到 start_at
获取 URL 内容(POST / Form,头部带令牌)
获取词典值(duplicate)           → 判断是否重复
显示通知                        → “已添加”或“已存在”
```

注意事项:

- iPhone 必须连着 Tailscale 才能访问该地址。
- 令牌会保存在快捷指令里。如果要分享这个快捷指令,请在**设置 → 远程接入令牌**里
  为对方单独生成一枚(用完直接撤销),不要把自己的令牌给别人。
- 快捷指令把「日期」变量直接塞进 Form 字段时,格式取决于系统语言设置;
  用「格式化日期」显式指定 `yyyy-MM-dd HH:mm` 最稳妥。
- 服务端返回 `201` 表示新建成功、`200` 且 `duplicate: true` 表示这次是重复提交。
  可以用「获取词典值」读取 `sync.ok` 确认 ICS 是否已同步。

#### timezone 怎么填

`timezone` 认三种写法:**IANA 名**(`Australia/Brisbane`)、**中文名**(`北京时间`)、
以及 `/admin/settings` 默认时区下拉框里的**序号**(`1` = 北京时间、`11` = 悉尼时间)。
偏移量与缩写(`+10:00`、`AEST`、`GMT+10`)仍会被拒:返回 `422`,`fields.timezone` 提示
「未识别的时区:…可填 IANA 名…也可填设置页列出的序号 1-30…」。

序号表固定不变(只会在末尾追加),完整清单见
[`docs/static/app-timezones.md`](static/app-timezones.md);也可以直接读接口:

```powershell
curl.exe -s http://localhost:443/api/v1/settings -H "Cookie: <登录后的会话>"
# → {"timezone_choices": [{"index": 1, "iana": "Asia/Shanghai", "label": "北京时间", ...}, ...]}
```

麻烦的地方在于:**快捷指令没有能取到设备 IANA 名的动作**。「转换时区」只认它自带的城市列表,
既拿不到当前时区的名字,也不接受用文本传进去的名字(见
[Apple Shortcuts and Time Zones](https://joe-steel.com/2025-03-31-Apple-Shortcuts-and-Time-Zones.html))。
序号就是为此准备的:在设置页看到「1. 北京时间」,快捷指令里填 `1` 即可。可行写法:

| 写法 | 表单字段 | 说明 |
|---|---|---|
| 不填(**推荐**) | 不添加 `timezone` | 服务端用 `DEFAULT_TIMEZONE`,本部署就是 `Australia/Brisbane` |
| 写死序号 | `timezone` = `1`(用「文本」动作,北京) | 最短、最不容易打错;序号含义见设置页下拉框 |
| 写死 IANA 名 | `timezone` = `Australia/Brisbane` | 与上一条等价,只是把意图显式写在快捷指令里 |
| 跟随手机当前时区 | `start_at` 用「格式化日期」输出**带偏移量**的时间(内置 `ISO 8601`,或自定义 `yyyy-MM-dd'T'HH:mm:ssZZZZZ`),`timezone` 仍填 `Australia/Brisbane` | 时刻由手机的偏移量决定;日历里仍按 `Australia/Brisbane` 还原显示 |

服务端如何解释时间(实测,`DEFAULT_TIMEZONE=Australia/Brisbane`):

| 提交 | 落库时刻 | 日历里显示为 |
|---|---|---|
| `start_at=2026-11-03T14:00:00` + `timezone=Australia/Brisbane`(或省略 `timezone`) | `2026-11-03T04:00:00Z` | 11-03 14:00(+10:00) |
| `start_at=2026-11-03T14:00:00+11:00` + `timezone=Australia/Brisbane` | `2026-11-03T03:00:00Z` | 11-03 **13:00**(+10:00) |
| `start_at=2026-11-03T14:00:00Z` | `2026-11-03T14:00:00Z` | 11-04 **00:00**(+10:00) |

两条规则:**带偏移量(或 `Z`)按该偏移量解释,不带偏移量按 `timezone` 解释**;而事件存下来的
`timezone` 决定它在日历和 ICS 里怎么显示。所以:

- 想要「永远是布里斯班时间 14:00 的日程」→ 发**不带偏移量**的本地时间(前两种写法)。
- 想要「此刻手机所在地的 14:00」→ 才发带偏移量的时间;注意它在日历里会换算成布里斯班时间。
- **不要**发 `...Z`——那是 UTC 语义,会被当成 14:00 世界时,在布里斯班直接跳到次日 0 点。

## 4. 数据与备份

`/data`(主机 `./data`)是唯一需要持久化和备份的应用数据目录:

```text
data/
├─ calendar.db          # SQLite 主库(WAL 模式)
├─ calendar.db-wal      # WAL 日志
├─ calendar.db-shm      # 共享内存索引
├─ admin.hash           # 管理员口令哈希(权限已收紧)
├─ session_secret       # 会话签名密钥
├─ export/calendar.ics  # 派生发布文件,可随时重建
├─ snapshots/           # 导出版本快照,供邮件重试使用
└─ backups/             # 命令行生成的备份
```

### 4.1 手动备份(推荐方式)

使用 SQLite 在线备份 API,生成一致快照,不会拷到写了一半的 WAL:

```powershell
docker compose exec calendar python -m app.cli backup
docker compose exec calendar python -m app.cli backups
```

备份同时会按 `BACKUP_RETENTION_DAYS`(默认 14 天)清理过期文件。

### 4.2 每天自动备份

后台任务每天会尝试清理过期备份。若需要自动**生成**备份,用 Windows 计划任务:

```powershell
schtasks /create /tn "SisiCalendar Backup" /sc daily /st 03:00 /tr ^
  "cmd /c cd /d D:\桌面\sisi_apps\SisiCalendar && docker compose exec -T calendar python -m app.cli backup"
```

### 4.3 备份哪些东西

| 对象 | 是否必须 | 说明 |
|---|---|---|
| `calendar.db` | 必须 | 日程数据的唯一事实来源 |
| `admin.hash` / `session_secret` | 建议 | 不备份会导致重新登录/换密钥 |
| `.env` | 必须,但**单独保存** | 含 SMTP 口令,不能和普通数据压缩包混放 |
| `export/calendar.ics` | 不需要 | 可由数据库重新生成,可留作诊断 |
| `snapshots/` | 不需要 | 仅用于邮件重试,过期会被清理 |

### 4.4 恢复流程

```powershell
# 1. 停止服务(必须,恢复期间不能有活动连接)
docker compose stop

# 2. 恢复(会先把当前库另存为 calendar.db.pre-restore)
docker compose run --rm calendar python -m app.cli restore /data/backups/calendar-20260101-030000.db

# 3. 启动并检查
docker compose up -d
docker compose exec calendar python -m app.cli verify
curl.exe -i http://localhost:443/readyz
```

`restore` 会一并清除 `-wal`/`-shm`,强制重新生成 ICS 并做一致性检查。
最后在 iPhone 上确认订阅内容已更新。

### 4.5 回退

如果恢复结果不对,把 `calendar.db.pre-restore` 改回 `calendar.db` 再重复上面的启动步骤即可。

## 8. 故障排查

| 现象 | 排查方向 |
|---|---|
| 容器不断重启 | `docker compose logs calendar`;常见原因是 `/data` 不可写或迁移失败 |
| `/readyz` 返回 503 | 看 `checks` 里哪一项为 false;`export` 为 false 时执行 `app.cli verify` |
| 页面显示「ICS 待修复」 | 备份目录权限、磁盘空间;后台任务每分钟重试,也可手动 `app.cli export --force` |
| iPhone 订阅不更新 | 确认 Tailscale 已连接、`/calendar` 可访问;必要时在 iPhone 上删除并重新添加订阅 |
| 邮件全部失败 | `app/sync` 页看错误摘要;确认 `SMTP_SECURITY` 与端口匹配(587=starttls,465=ssl) |
| 邮件部分失败 | 单个地址被拒不影响其他人;修正后在该行点「重试」 |
| 收不到初始口令 | `docker compose logs calendar \| Select-String "管理员口令"`,或重新注入 `ADMIN_PASSWORD_HASH` |
| 忘记口令 | `uv run python -m app.cli hash-password` 生成新哈希写入 `.env` 后 `docker compose up -d` |
| 主机重启后服务未恢复 | `docker compose ps`;确认 `restart: unless-stopped` 生效且 Docker Desktop 已开机自启 |

### 8.1 Linux 主机上的权限问题

镜像以非 root 用户(uid 10001)运行。Docker Desktop for Windows 的绑定挂载会自动处理权限,
但在原生 Linux 上首次部署可能需要:

```bash
sudo chown -R 10001:10001 ./data
```
