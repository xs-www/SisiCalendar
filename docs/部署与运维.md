# 部署与运维

本文覆盖 Docker Desktop 部署、Tailscale Serve 暴露订阅入口、备份恢复、升级回滚与故障排查。

对应开发文档第 9、10、12 节。设计文档里的 `http://localhost:443/admin` 是**本机管理地址**,
端口号虽然是 443,容器内外都走 HTTP,HTTPS 由 Tailscale 在外层终止。

---

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 主机 + Docker Desktop(WSL2 后端) |
| Docker | 24 以上,含 Compose v2(`docker compose version` 可用) |
| Tailscale | 已登录 `sisi-laptop`,MagicDNS 名称 `sisi-laptop.tail921448.ts.net` |
| 端口 | 主机 443 空闲(仅绑定 `127.0.0.1`,不占用局域网) |
| 磁盘 | `/data` 所在盘预留空间;SQLite 单用户负载很小 |

## 2. 首次部署

### 2.1 准备配置文件

```powershell
cd D:\桌面\sisi_apps\SisiCalendar
Copy-Item .env.example .env
notepad .env
```

至少确认以下项:

```dotenv
DATA_DIR=/data
ADMIN_USERNAME=admin
# 推荐:先算出哈希再填,避免明文口令进入 .env
# ADMIN_PASSWORD_HASH=$argon2id$v=19$m=65536,t=3,p=4$....
SESSION_SECRET=            # 留空则首次启动自动生成并写入 /data/session_secret
DEFAULT_TIMEZONE=Australia/Brisbane
SUBSCRIPTION_URL=https://sisi-laptop.tail921448.ts.net/calendar
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_USERNAME=you@example.com
SMTP_PASSWORD=应用专用密码
SMTP_FROM_ADDRESS=you@example.com
```

生成管理员口令哈希(明文不会写入任何文件):

```powershell
uv run python -m app.cli hash-password
```

> 如果既没有 `ADMIN_PASSWORD_HASH` 也没有 `ADMIN_PASSWORD`,首次启动会随机生成口令并
> **只在容器日志里打印一次**,同时把哈希写入 `/data/admin.hash`。错过日志就用
> `docker compose exec calendar python -m app.cli credential` 查看来源,或重新注入哈希。

### 2.2 启动

```powershell
docker compose up -d --build
docker compose logs -f calendar
```

启动流程会自动完成:`/data` 目录准备 → Alembic 迁移到最新版本 → 数据库与 ICS 一致性检查
→ 恢复中断的发信任务 → 启动后台任务(每分钟修复 ICS、轮询邮件队列)。

### 2.3 本机验证

```powershell
curl.exe -i http://localhost:443/healthz
curl.exe -i http://localhost:443/readyz
curl.exe -i http://localhost:443/calendar
```

- `/healthz` 返回 `{"status":"ok"}` 表示进程存活。
- `/readyz` 返回 `200` 且 `checks` 全为 `ok` 表示数据库、数据目录与导出状态都正常。
- `/calendar` 返回 `Content-Type: text/calendar; charset=utf-8`。

浏览器打开 `http://localhost:443/admin` 登录后应看到月历视图。

### 2.4 关闭对外暴露(重要)

Compose 里端口必须写成 `127.0.0.1:443:8000`。一旦省略主机 IP,Docker 会绑定 `0.0.0.0`,
管理界面就会出现在局域网中。可用下面的命令确认绑定地址:

```powershell
docker compose ps
netstat -ano | findstr :443
```

`netstat` 结果应只出现 `127.0.0.1:443`,不应出现 `0.0.0.0:443` 或 `[::]:443`。

## 3. Tailscale Serve:只暴露 /calendar

> **警告**:`tailscale serve` 是**整机配置**。在已有路由的机器上操作前必须先保存快照,
> 避免误删其他入口。

```powershell
# 1. 先看现状并留存
tailscale serve status | Tee-Object -FilePath tailscale-serve-backup.txt

# 2. 新增 /calendar 路由(不会重置其他路径)
tailscale serve --bg --yes --https=443 --set-path=/calendar http://127.0.0.1:443
```

期望结果:

```text
https://sisi-laptop.tail921448.ts.net/calendar
|-- proxy http://127.0.0.1:443
```

### 3.1 必须确认不能访问的路径

```powershell
# 以下三条在 tailnet 内应当返回 404 / 403,绝不能返回登录页或数据
curl.exe -i https://sisi-laptop.tail921448.ts.net/admin
curl.exe -i https://sisi-laptop.tail921448.ts.net/api/v1/events
curl.exe -i https://sisi-laptop.tail921448.ts.net/api/v1/sync/status

# 只有订阅入口可用
curl.exe -i https://sisi-laptop.tail921448.ts.net/calendar
```

因为 Serve 只挂了 `/calendar` 一条路径,其他路径不会转发到容器。若发现 `/admin` 可访问,
说明存在额外的 Serve 路由或 Funnel 配置,必须立即排查。

### 3.2 ACL 建议

在 tailnet ACL 中只允许指定用户或设备访问该节点的 Serve:

```jsonc
{
  "acls": [
    // 只有自己的设备可以访问 sisi-laptop 的 Serve 服务
    { "action": "accept", "src": ["autogroup:member"], "dst": ["sisi-laptop:443"] }
  ]
}
```

按需收紧到具体设备标签。**不要**启用 `tailscale funnel`——那会把私人日历暴露到公网。

### 3.3 iPhone 订阅

1. iPhone 打开 Tailscale 并确认已连接。
2. 设置 → 日历 → 账户 → 添加账户 → 其他 → 添加已订阅的日历。
3. 服务器填 `https://sisi-laptop.tail921448.ts.net/calendar`。
4. 关闭 Tailscale 时系统日历保留最后一次缓存;恢复连接后自动拉取新版本。

## 4. 数据与备份

`/data`(主机 `./data`)是唯一需要持久化和备份的应用数据目录:

```text
data/
├─ calendar.db          # SQLite 主库(WAL 模式)
├─ calendar.db-wal      # WAL 日志
├─ calendar.db-shm      # 共享内存索引
├─ admin.hash           # 管理员口令哈希(权限已收紧)
├─ session_secret       # 会话签名密钥
├─ export/calendar.ics  # 派生发布文件,可随时重建
├─ snapshots/           # 导出版本快照,供邮件重试使用
└─ backups/             # 命令行生成的备份
```

### 4.1 手动备份(推荐方式)

使用 SQLite 在线备份 API,生成一致快照,不会拷到写了一半的 WAL:

```powershell
docker compose exec calendar python -m app.cli backup
docker compose exec calendar python -m app.cli backups
```

备份同时会按 `BACKUP_RETENTION_DAYS`(默认 14 天)清理过期文件。

### 4.2 每天自动备份

后台任务每天会尝试清理过期备份。若需要自动**生成**备份,用 Windows 计划任务:

```powershell
schtasks /create /tn "SisiCalendar Backup" /sc daily /st 03:00 /tr ^
  "cmd /c cd /d D:\桌面\sisi_apps\SisiCalendar && docker compose exec -T calendar python -m app.cli backup"
```

### 4.3 备份哪些东西

| 对象 | 是否必须 | 说明 |
|---|---|---|
| `calendar.db` | 必须 | 日程数据的唯一事实来源 |
| `admin.hash` / `session_secret` | 建议 | 不备份会导致重新登录/换密钥 |
| `.env` | 必须,但**单独保存** | 含 SMTP 口令,不能和普通数据压缩包混放 |
| `export/calendar.ics` | 不需要 | 可由数据库重新生成,可留作诊断 |
| `snapshots/` | 不需要 | 仅用于邮件重试,过期会被清理 |

### 4.4 恢复流程

```powershell
# 1. 停止服务(必须,恢复期间不能有活动连接)
docker compose stop

# 2. 恢复(会先把当前库另存为 calendar.db.pre-restore)
docker compose run --rm calendar python -m app.cli restore /data/backups/calendar-20260101-030000.db

# 3. 启动并检查
docker compose up -d
docker compose exec calendar python -m app.cli verify
curl.exe -i http://localhost:443/readyz
```

`restore` 会一并清除 `-wal`/`-shm`,强制重新生成 ICS 并做一致性检查。
最后在 iPhone 上确认订阅内容已更新。

### 4.5 回退

如果恢复结果不对,把 `calendar.db.pre-restore` 改回 `calendar.db` 再重复上面的启动步骤即可。

## 5. 升级与回滚

### 5.1 升级

```powershell
# 1. 先备份
docker compose exec calendar python -m app.cli backup

# 2. 拉取/构建新版本
git pull                      # 或替换代码目录
docker compose build
docker compose up -d

# 3. 迁移会自动执行,确认健康状态
docker compose ps
curl.exe -i http://localhost:443/readyz
```

### 5.2 回滚

```powershell
docker compose down
git checkout <上一个可用版本>
docker compose build
docker compose up -d
# 若新版本改过表结构,再执行一次恢复
docker compose stop
docker compose run --rm calendar python -m app.cli restore /data/backups/<升级前备份>.db
docker compose up -d
```

## 6. 日常运维

```powershell
docker compose logs -f calendar            # 跟踪日志
docker compose restart calendar            # 重启
docker compose exec calendar python -m app.cli verify          # 一致性检查 + 自动修复
docker compose exec calendar python -m app.cli export --force  # 强制重新生成 ICS
docker compose exec calendar python -m app.cli process-mail    # 立即处理一次发信队列
docker compose exec calendar python -m app.cli credential      # 查看管理员凭据来源
```

邮件发送失败时,在 `http://localhost:443/admin/sync` 可以看到失败人员、原因、重试次数与
下次重试时间,并支持逐条手动重试。

## 7. 端口与安全清单

- [ ] `docker compose ps` 显示端口绑定为 `127.0.0.1:443->8000/tcp`
- [ ] `netstat -ano | findstr :443` 没有 `0.0.0.0` 或 `[::]`
- [ ] `http://localhost:443/admin` 需要登录
- [ ] tailnet 内 `https://<节点>/admin`、`/api/v1/events` 不可访问
- [ ] `https://<节点>/calendar` 返回 200 且内容为 iCalendar
- [ ] 未启用 Tailscale Funnel
- [ ] `.env` 不在版本库中(`git status` 应看不到)
- [ ] `data/` 不在版本库中
- [ ] SMTP 使用应用专用密码,未使用主账号口令

## 8. 故障排查

| 现象 | 排查方向 |
|---|---|
| 容器不断重启 | `docker compose logs calendar`;常见原因是 `/data` 不可写或迁移失败 |
| `/readyz` 返回 503 | 看 `checks` 里哪一项为 false;`export` 为 false 时执行 `app.cli verify` |
| 页面显示「ICS 待修复」 | 备份目录权限、磁盘空间;后台任务每分钟重试,也可手动 `app.cli export --force` |
| iPhone 订阅不更新 | 确认 Tailscale 已连接、`/calendar` 可访问;必要时在 iPhone 上删除并重新添加订阅 |
| 邮件全部失败 | `app/sync` 页看错误摘要;确认 `SMTP_SECURITY` 与端口匹配(587=starttls,465=ssl) |
| 邮件部分失败 | 单个地址被拒不影响其他人;修正后在该行点「重试」 |
| 收不到初始口令 | `docker compose logs calendar \| Select-String "管理员口令"`,或重新注入 `ADMIN_PASSWORD_HASH` |
| 忘记口令 | `uv run python -m app.cli hash-password` 生成新哈希写入 `.env` 后 `docker compose up -d` |
| 主机重启后服务未恢复 | `docker compose ps`;确认 `restart: unless-stopped` 生效且 Docker Desktop 已开机自启 |

### 8.1 Linux 主机上的权限问题

镜像以非 root 用户(uid 10001)运行。Docker Desktop for Windows 的绑定挂载会自动处理权限,
但在原生 Linux 上首次部署可能需要:

```bash
sudo chown -R 10001:10001 ./data
```

### 8.2 数据目录迁移

```powershell
docker compose down
Move-Item .\data D:\sisi-calendar-data
# 修改 compose.yaml 的卷映射为 D:\sisi-calendar-data:/data
docker compose up -d
```
